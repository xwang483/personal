# 刊邮

读者用**完整手机号**查询杂志邮寄单号的小网站。数据来自管理人员上传的 Excel 或 CSV，不连接任何快递公司。

知道完整手机号的人就能查到该号码下已导入的单号。这是明确的产品决定：不要求姓名、订单号或验证码。查询结果只包含杂志名称、寄出日期、邮寄方式和快递单号。

## 本地运行

需要 Node.js 22。

```bash
npm install
cp .env.example .env.local
```

在 `.env.local` 里填写 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 和 `ADMIN_SESSION_SECRET` 后启动。会话密钥可以用 `openssl rand -base64 32` 生成。程序没有默认密码，也不会把密码写进页面或日志。

```bash
npm run dev
```

开发服务器默认是 [http://localhost:3000](http://localhost:3000)。读者页是 `/`，管理人员入口是 `/admin`。

```bash
npm test
npm run lint
```

## 第一次配置管理员

三个环境变量缺一不可，否则登录和上传都会拒绝，并提示尚未配置：

| 变量 | 要求 |
| --- | --- |
| `ADMIN_USERNAME` | 1 到 64 个字符 |
| `ADMIN_PASSWORD` | 至少 8 位，请自行使用长随机密码 |
| `ADMIN_SESSION_SECRET` | 至少 32 位，用来签名登录会话 |

修改密码后，旧的登录会话会失效。会话写在 `HttpOnly` cookie 里，大约 12 小时过期。生产环境请使用 HTTPS，cookie 会带 `Secure`。

## 表格格式

第一行必须是表头，列名要完全一致。空白间隔列可以留着，会被忽略。多出来的未知列也会忽略。缺少下面任一列表头时，整份文件会被拒绝：

`姓名`、`收货地址`、`邮寄方式`、`单号`、`日期`、`电话`、`杂志名称`、`订单号`

登录后可以下载空白模板和虚构示例（CSV 或 xlsx）。示例里的姓名、地址和单号都是虚构的，杂志名称带「示例」。姓名和收货地址**不会写入数据库**，也不会出现在查询结果里。示例手机号是 `13800001111`（两本杂志）和 `13900002222`（一本）。

支持：

- `.xlsx`（不要带宏，不要加密）
- UTF-8 CSV，可以带 BOM
- GB18030 CSV

限制：5MB，最多 1 万行数据，只读第一个工作表。

日期可以写成 `2026-03-02`、`2026/3/2`、`2026年3月2日`，或 Excel 日期。电话必须能规范成中国大陆 11 位手机号。`+86`、`86`、`0086`、空格、短横线和 Excel 末尾的 `.0` 都可以。只填一部分号码不会拿去搜索。

`电话`、`单号`、`订单号` 请在 Excel 里设为**文本**。超过可精确表示的整数范围（约 15 位以上）时，Excel 可能已经把末尾改掉。这种行会在校验里被拒绝，并说明精度损失无法恢复，不会把改坏的单号写进库。

## 导入

上传后先在服务器上校验。页面列出错误行，以及可通过记录的杂志、日期、邮寄方式和单号；手机号只显示掩码。确认之后才会写入。

重复导入是幂等的：

- 有订单号时，同一手机号、杂志名称和订单号视为同一条。日期、邮寄方式或单号有变化就更新
- 没有订单号时，同一手机号、杂志名称和单号视为同一条
- 完全相同的记录计为「未变化」，不会多出一行

没有删除界面。如果一条记录完全导错，需要先备份，再直接处理 SQLite 文件。

## 查询与隐私

`POST /api/lookup` 只接受一个手机号。成功时只返回杂志名称、日期、邮寄方式和快递单号，不返回姓名、地址、手机号、订单号，也不返回别人的记录。

这里不拉取物流轨迹，也没有到达预估。韵达和中通可以另开官方查询页，见下一节。

默认每个来源 10 分钟最多查询 20 次，登录尝试 15 分钟最多 8 次。没有公开的批量导出。服务器日志不记录手机号、姓名、地址、密码或文件内容。

限流计数存在进程内存里，重启后清零。站点放在反向代理后面时，设置 `TRUST_PROXY=1`，否则所有访客会共用一个计数。不设这个值时，程序不信任 `X-Forwarded-For`。

## 跳转到快递公司查询页

读者结果里的「查询物流」只认识韵达和中通。匹配的是「邮寄方式」的别名，不是单号本身，也不会把表格里的任意文字当成网址。

2026-11-12 核对过的官方页面：

| 快递 | 打开的地址 | 页面上有什么 |
| --- | --- | --- |
| 韵达 | https://web.yundaex.com/Home | 「运单号查询」表单 |
| 中通 | https://www.zto.com/check | 「运单查询」表单 |

这两个地址都没有可核实的单号参数。韵达当前页面脚本不读取网址中的单号；`https://www.yundaex.com/cn/trackResult?mailNo=` 返回 404，没有采用。中通公开页面同样看不到可用的单号参数。因此不会把单号拼进链接，也不会声称页面会自动填入。

别名（忽略大小写和空格）：

- 韵达、韵达快递、韵达速递、YUNDA、YUNDAEX
- 中通、中通快递、中通速递、ZTO

点击「查询物流」会先尝试复制单号，再在新标签打开上表中的固定地址。复制失败时仍打开页面，并提示需要手动输入。链接只带快递公司自己的地址，不附带手机号、姓名或地址。

顺丰、邮政、京东以及其他写不上表的邮寄方式没有外链，只保留复制，并说明暂不能跳转。

## 存储和部署

数据在单个 SQLite 文件，默认是 `data/shipments.sqlite`。这是单实例方案：只运行一个写入进程，并把 `data/` 挂到持久卷。没有持久盘时，导入的数据会在实例更换后丢失。不要同时跑多个写入进程。

备份时复制主库和旁边的 `-wal` 文件，或先做 checkpoint。不要把 `data/` 和 `.env.local` 提交到仓库。

```bash
npm run build
npm start
```

本仓库按草稿保存，没有做公开部署。
